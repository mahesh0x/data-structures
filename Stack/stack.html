The core structure

In Python you don’t need a special class — a plain list is a stack:

stack = []
stack.append(x)      # push
top = stack[-1]      # peek (don't remove)
x = stack.pop()      # pop (LIFO — last in, first out)

The only rules: you always add and remove from the same end ([-1]), and you never index into the middle. That LIFO discipline is what makes a stack model “most recent first.”

The one idea: is the most recent unresolved thing what decides?

The habit

“When I process the current element, is the thing it interacts with the most recently seen one that hasn’t been dealt with yet?”

If yes, that’s a stack. Look at how uniformly this fits:

  • A closing bracket must match the most recent unmatched opening bracket.
  • A warmer temperature resolves the most recent colder day still waiting for a warmer one.
  • An operator in RPN consumes the two most recent operands.
  • A slower car ahead absorbs the most recent faster car behind it.

Every time the answer is “the latest thing I haven’t finished with,” you push while you’re unsure and pop the moment the current element resolves what’s on top.

Pattern A: matching and balancing

Push openers; when you hit a closer, pop and check it matches. If the stack is empty at the end, everything paired up.

def isValid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for c in s:
        if c in pairs:                        # a closer
            if not stack or stack.pop() != pairs[c]:
                return False
        else:                                 # an opener
            stack.append(c)
    return not stack                          # leftovers mean unclosed openers

Pattern B: the monotonic stack — this section’s real payload

This is the pattern that makes the stack section click. You keep the stack in sorted order (increasing or decreasing); before pushing the current element, you pop everything that the current element resolves.

The insight worth memorising

When you pop an element, you’ve found that element’s answer for free — because the current element is the first thing bigger (or smaller) than it that you’ve encountered. The pop is not cleanup; the pop is the computation.

def dailyTemperatures(temps):
    stack = []                                # indices, temps decreasing bottom->top
    result = [0] * len(temps)
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()                   # t is the "next warmer" for day j
            result[j] = i - j
        stack.append(i)
    return result                             # anything left has no warmer day: stays 0
Which direction should the stack be sorted?

Work backwards from what you pop. You pop when the current element resolves the top. For “next greater,” the current element resolves smaller tops → so tops must be smaller than what’s below → the stack is decreasing bottom→top, and you pop while stack[-1] < current. For “next smaller,” flip both.

Pattern C: the stack as a running computation

In Evaluate Reverse Polish Notation the stack isn’t bookkeeping — it is the calculation. Push numbers; on an operator, pop the top two, apply, push the result.

Techniques you’ll reuse

A stack can carry auxiliary info alongside the value

Min Stack keeps, at each level, both the pushed value and the minimum of everything at or below it — so getMin is O(1) because the current minimum is always sitting right on top.

Process in a deliberate order

Car Fleet isn’t obviously a stack problem until you sort cars by starting position descending and walk them — each car either joins the fleet ahead (gets absorbed) or forms a new fleet. That’s a stack of fleet arrival-times where you pop/merge when a car would catch the one ahead.

Recursion uses the call stack — so “generate all” belongs here too

Generate Parentheses is really backtracking (an explicit stack of choices), included in this section because the balance rule — you can only add ) when open count exceeds close count — is a stack-validity invariant. See Backtracking for the full choose/explore/un-choose treatment.

def generateParenthesis(n):
    res, path = [], []
    def backtrack(open_count, close_count):
        if len(path) == 2 * n:
            res.append("".join(path)); return
        if open_count < n:                     # can always open while budget remains
            path.append("("); backtrack(open_count + 1, close_count); path.pop()
        if close_count < open_count:           # can only close what is already open
            path.append(")"); backtrack(open_count, close_count + 1); path.pop()
    backtrack(0, 0)
    return res

Largest Rectangle in Histogram — the boss

Everything above converges here. Each bar wants to know: how far left and right can I extend before I hit something shorter than me? A monotonic increasing stack answers both at once, because the moment a bar is popped, both of its boundaries are known.

def largestRectangleArea(heights):
    stack = []                      # (start_index, height), heights increasing
    best = 0
    for i, h in enumerate(heights):
        start = i
        while stack and stack[-1][1] > h:
            idx, height = stack.pop()
            best = max(best, height * (i - idx))
            start = idx             # this bar can extend back to where the taller one began
        stack.append((start, h))
    for idx, height in stack:       # drain: these extend to the far right edge
        best = max(best, height * (len(heights) - idx))
    return best

Suggested order to attack them

  1. Valid ParenthesesThe canonical push/pop match. Handle all three failure modes.
  2. Min StackStack with extra bookkeeping — a design problem. Store the min per level, not in one variable.
  3. Evaluate Reverse Polish NotationStack as a calculator. Watch operand order and truncation-toward-zero division.
  4. Generate ParenthesesBalance invariant + backtracking. Two conditions govern the two choices.
  5. Daily TemperaturesYour first monotonic stack — internalise “the pop is the answer.”
  6. Car FleetA monotonic stack hiding behind a sort. The insight is the traversal order.
  7. Largest Rectangle in HistogramThe boss — monotonic stack computing widths on pop, plus the inherited start index and the final drain.

By the time you reach Largest Rectangle in Histogram, the “pop resolves the popped element’s answer” idea from Daily Temperatures will be the thing that makes the width computation make sense instead of looking like magic.

Traps

Trap 1 — popping an empty stack

Always guard: if not stack or stack.pop() != expected. A closer with no opener is a real test case, not a corner case.

Trap 2 — forgetting the leftovers

Both Valid Parentheses (unclosed openers) and Largest Rectangle (bars that reach the right edge) need an explicit check after the loop ends.

Trap 3 — < vs <= in the monotonic pop

With equal heights, popping on <= versus < changes whether equal-valued neighbours merge. For Daily Temperatures either works; for Largest Rectangle, popping on strict > and letting equal bars inherit the earlier start index is what keeps equal-height runs correct.

Trap 4 — using pop(0)

list.pop(0) is O(n) because it shifts everything. That’s a queue operation; use collections.deque if you genuinely need one.

One practical tip

Name the invariant, then name the pop

When you suspect a monotonic stack, write the invariant before coding — # stack holds indices, temps decreasing from bottom to top — and then, for the pop step, write what the answer is at the moment you pop. Naming what a pop means is the whole trick of this section.
