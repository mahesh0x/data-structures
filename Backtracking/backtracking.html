Why this section is so rewarding

Backtracking is one of the most rewarding sections in NeetCode 150 to build real pattern recognition in, because once the core move clicks, all nine problems collapse into the same template.

There’s no custom data structure here — you’re just walking a decision tree over a list, string, or grid — so the entire difficulty is figuring out what a “choice” is at each step and when you’ve reached a complete answer.

The one habit: choose → explore → un-choose

Every backtracking problem is a depth-first walk over a tree of decisions. At each node you:

  1. Choose — add a candidate to your current partial solution (path).
  2. Explore — recurse to make the next decision, with that choice in place.
  3. Un-choose — remove the candidate you just added, so the next iteration of the loop starts from a clean slate.
def backtrack(start, path):
    if is_complete(path):          # reached a valid full solution
        result.append(path[:])     # append a COPY — path keeps mutating
        return
    for choice in choices(start):  # each option at this step
        path.append(choice)        # choose
        backtrack(next(start), path)  # explore
        path.pop()                 # un-choose
Burn these two into muscle memory

1. Append a copy (path[:]) when you record a solution. If you append path itself, every stored answer points at the same list that keeps changing under you — and you end with N identical empty lists.

2. Every append is paired with a pop. If you can write those two lines correctly, you’ve solved most of this section.

Technique patterns — know these cold

1. Pick / skip via a start index

For subsets and combinations, pass a start so each recursion only considers elements from start onward. This is what stops [1,2] and [2,1] from both appearing when you only want one.

def backtrack(start, path):
    result.append(path[:])              # subsets: record at every node
    for i in range(start, len(nums)):
        path.append(nums[i])
        backtrack(i + 1, path)          # i+1 → never look back
        path.pop()
The one-character difference that changes the problem

backtrack(i + 1, ...) → each element used at most once (Subsets, Combination Sum II).
backtrack(i, ...) → the same element may be reused (Combination Sum).
backtrack(0, ...) → order matters and elements repeat — usually not what you want.

2. Use a used[] array for permutations

Order matters, so you can look backward; you just can’t reuse an element already in the current path.

def backtrack(path, used):
    if len(path) == len(nums):
        result.append(path[:]); return
    for i in range(len(nums)):
        if used[i]: continue
        used[i] = True;  path.append(nums[i])
        backtrack(path, used)
        path.pop();      used[i] = False

3. Skip duplicate siblings — the “II” trick

Sort the input first, then within a single for loop skip any element equal to the previous one, so you don’t start two branches with the same value at the same depth.

nums.sort()
for i in range(start, len(nums)):
    if i > start and nums[i] == nums[i - 1]:
        continue                        # same value already tried at this depth
    path.append(nums[i])
    backtrack(i + 1, path)
    path.pop()

4. Grid DFS with in-place marking

For Word Search, a “choice” is a direction; mark the current cell (overwrite it or use a visited set) before recursing into neighbours, then restore it on the way out — the un-choose step applied to a 2-D board.

N-Queens — the capstone

Same loop, three pruning conditions. The insight that makes it fast is representing the constraints as sets you can test in O(1).

def solveNQueens(n):
    cols, diags, anti = set(), set(), set()
    board, res = [], []

    def backtrack(r):
        if r == n:
            res.append(["".join(row) for row in board]); return
        for c in range(n):
            if c in cols or (r - c) in diags or (r + c) in anti:
                continue                                  # prune
            cols.add(c); diags.add(r - c); anti.add(r + c)      # choose
            board.append("." * c + "Q" + "." * (n - c - 1))
            backtrack(r + 1)                                    # explore
            board.pop()
            cols.remove(c); diags.remove(r - c); anti.remove(r + c)  # un-choose
    backtrack(0)
    return res

Suggested order to attack them

  1. SubsetsLearn the pick/skip + start template. Record at every node.
  2. Combination SumSame shape, but reuse allowed → recurse with i. Prune when the remaining target goes negative.
  3. PermutationsSwitch to a used[] array; order matters, so backward looks are legal.
  4. Subsets IIAdd the sort + skip-duplicate-siblings move. Watch i > start, not i > 0.
  5. Combination Sum IICombine “II” dedup with the target-sum stop, and each element used at most once.
  6. Letter Combinations of a Phone NumberChoices come from a digit→letters map. The base case is index == len(digits).
  7. Palindrome PartitioningChoice = where to cut; prune with an is-palindrome check before recursing.
  8. Word SearchBacktracking on a 2-D grid with in-place marking — and restoring.
  9. N-QueensConstraint pruning with column + both diagonal sets. The capstone.

By the time you hit N-Queens, the “choose → recurse → un-choose” loop and the “append a copy at the base case” move will feel automatic; N-Queens is just that same loop wearing three pruning conditions.

Traps

Trap 1 — appending the path itself

result.append(path) stores a reference. Every entry ends up identical (usually empty). Always path[:] or list(path).

Trap 2 — a missing pop

An append without its matching pop leaks state into sibling branches. If your answers keep growing longer and longer, this is why.

Trap 3 — i > 0 instead of i > start

The dedup guard is about siblings at one level, not about the path. Using i > 0 silently drops legitimate answers containing repeated values.

Trap 4 — forgetting to restore grid state

Word Search works on the first call and fails afterwards. Restore the cell on the way out, on every return path.

Trap 5 — pruning after recursing instead of before

Checking legality inside the recursive call still explores the node. Prune in the loop, before append, so the whole subtree is never entered.

One practical tip

Write these two comments first

# choice at each step: ...
# record when: ...

Those two sentences pin down your for loop and your base case, which is the entire skeleton. Fill in the pruning last.
