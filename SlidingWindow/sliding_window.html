Sliding Window

The pattern for “find the best or valid contiguous stretch.” The pointers are trivial; the entire difficulty is bookkeeping — keeping validity as one number you can update in O(1).

What makes it its own section

Sliding Window is really a specialised two-pointer technique where both pointers move in the same direction and the region between them — the window — is the thing you’re reasoning about.

The reason it deserves its own section is that the hard part isn’t the pointers. It’s knowing exactly when the window is valid, and updating your running state in O(1) as the window’s edges move, so the whole thing stays O(n) instead of collapsing back into an O(n·k) recount.

The trigger word is “contiguous”

Subarray, substring, consecutive stretch, window of size k. If the problem would still make sense after shuffling the input, it is not a sliding-window problem — that’s a hashing or sorting problem. Sliding window exploits adjacency, and nothing else.

The one idea: name your shrink condition

The habit

“My right pointer always moves forward to include new elements — but under what condition do I move left forward to evict elements from the left?”

That shrink condition is the problem. If you can state it in one sentence before coding, you’re done thinking. If you can’t, you don’t yet know what makes the window valid — and that, not the loop, is the actual problem.

The two shapes

Variable size

Grow right greedily; the moment the window breaks a constraint, advance left to repair it.

Used by: Longest Substring Without Repeating, Longest Repeating Character Replacement, Minimum Window Substring.

Fixed size

Size k is given. right and left move together keeping constant width; add the entering element, remove the leaving one.

Used by: Permutation in String, Sliding Window Maximum.

variable-size template
left = 0
state = {}                       # whatever you need to test validity in O(1)
best = 0
for right in range(len(s)):
    # add s[right] to state
    while window_is_invalid(state):
        # remove s[left] from state
        left += 1
    best = max(best, right - left + 1)   # or min, for "shortest valid window"
return best

The single subtlety that flips the template

For “longest valid” you record the answer after repairing — the window is only legal once the while-loop exits.
For “shortest valid” (Minimum Window Substring) you record while the window is valid, and keep shrinking to try to make it even smaller. The record statement lives inside the while loop, not after it.

Techniques you’ll reuse

1. Keep a frequency map of the current window

Most string-window problems track counts of characters currently inside [left, right]. Growing adds one; shrinking subtracts one (and deletes the key when it hits zero, so len(map) means “distinct characters in the window”). Validity is a check against that map.

2. Track validity as a single number, not a rescan

This is the move that keeps sliding window O(n). Don’t recompute the window’s property from scratch each step — maintain it incrementally.

Permutation in String uses the same principle differently: keep a matches counter of how many of the 26 letters have exactly the right count, and update it by ±1 as characters enter and leave. Validity becomes an O(1) matches == 26 check instead of comparing two 26-element arrays every step.

3. A monotonic deque for window max/min

Sliding Window Maximum is the odd one out: a frequency map won’t give you the max in O(1). Instead keep a deque of indices whose values are decreasing; the front is always the current max.

from collections import deque
def maxSlidingWindow(nums, k):
    dq = deque()                     # holds indices, values decreasing front->back
    res = []
    for right in range(len(nums)):
        while dq and nums[dq[-1]] < nums[right]:
            dq.pop()                 # dominated: smaller AND older
        dq.append(right)
        if dq[0] <= right - k:       # front index slid out of the window
            dq.popleft()
        if right >= k - 1:
            res.append(nums[dq[0]])  # front is the max of the current window
    return res

4. Best Time to Buy and Sell Stock is a window in disguise

left = buy day, right = sell day. If price[right] < price[left], move left to right (a cheaper buy day); otherwise the profit is price[right] - price[left]. It’s the gentlest introduction to the two-pointer sweep, and it’s equally natural as “track the min seen so far.”

def maxProfit(prices):
    buy, best = 0, 0
    for sell in range(1, len(prices)):
        if prices[sell] < prices[buy]:
            buy = sell                       # cheaper buy day — jump left here
        else:
            best = max(best, prices[sell] - prices[buy])
    return best

Minimum Window Substring — the boss

The trickiest bookkeeping in the section, because you have to track not just counts but how close to satisfied the window is. The device that makes it manageable is a have/need pair.

from collections import Counter
def minWindow(s, t):
    if not t or not s:
        return ""
    need = Counter(t)
    need_total, have = len(need), 0
    window = {}
    best, best_range = float("inf"), (0, 0)
    left = 0
    for right, ch in enumerate(s):
        window[ch] = window.get(ch, 0) + 1
        if ch in need and window[ch] == need[ch]:
            have += 1
        while have == need_total:                 # valid — try to shrink
            if right - left + 1 < best:
                best = right - left + 1
                best_range = (left, right)
            lch = s[left]
            window[lch] -= 1
            if lch in need and window[lch] < need[lch]:
                have -= 1
            left += 1
    l, r = best_range
    return s[l:r + 1] if best != float("inf") else ""

Suggested order to attack them

  1. Best Time to Buy and Sell StockThe gentlest left/right sweep. Solve it both as a window and as “min so far” and notice they’re the same code.
  2. Longest Substring Without Repeating CharactersFirst real variable window. Do the set version, then the “jump left directly” dict-of-last-index version.
  3. Longest Repeating Character ReplacementAdd the max_freq-in-window trick and be ready to justify never decreasing it.
  4. Permutation in StringSwitch to a fixed-size window with count matching. Push for the O(1) matches counter, not a 26-array comparison each step.
  5. Sliding Window MaximumLearn the monotonic deque. Two eviction rules, two ends.
  6. Minimum Window SubstringThe boss: shortest-valid window with have/need counting. The record statement moves inside the while loop.

By the time you reach Minimum Window Substring, the “grow right, shrink left, keep validity as one number” loop from problems 2–3 will be automatic, and you’ll only be adding the have/need counter on top of a loop shape you already trust.

Traps

Trap 1 — recording the answer in the wrong place

Longest → after the shrink loop. Shortest → inside it. Get this backwards and the code still runs.

Trap 2 — off-by-one in the width

The window [left, right] is inclusive, so its width is right - left + 1. Forgetting the +1 is the single most frequent typo in this section.

Trap 3 — rescanning inside the loop

Calling max(counts.values()) or comparing two 26-element arrays on every step turns O(n) into O(26n) — survivable — or, worse, recomputing over the window itself turns it into O(n·k). Maintain state incrementally.

Trap 4 — leaving zero-count keys in the map

If you use len(window) as “number of distinct characters,” you must del a key when its count drops to zero. Otherwise stale keys inflate the count forever.

One practical tip

Write these two comments first

# window is valid when: ...
# shrink from the left when: ...

Filling in those two blanks is 90% of every problem in this section; the pointer mechanics are identical every time.
