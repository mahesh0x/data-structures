Why mixed sets, not more drilling

Practising one topic at a time teaches you to solve problems when you already know which pattern applies. An interview does not tell you that. Mixed sets restore the missing skill: reading a cold problem and picking the tool.

How to use them

Each set is a self-checking harness (like every practice.py in this repo). To revise:

cp practice_set_1.py practice_set_1_copy.py   # keep the stubs pristine
python3 practice_set_1_copy.py                 # fill in the methods, watch FAIL -> PASS

Shared tree/linked-list builders live in practice_helpers.py, imported by each set.

Suggested rhythm

Work a set in one sitting without looking anything up. For each problem, before writing code, say out loud which pattern it is and why — that is the skill being trained. Afterwards, re-read the relevant topic page for anything you misclassified, not for anything you merely got wrong.

Interview-specific sets

Besides the topic-balanced sets above, themed sets drill a specific interview’s predicted problems — grouped by pattern, not one-per-topic:

practice_set_coderabbit.py

The 15-problem drill from practice_coderabbit.md (CodeRabbit phone screen). Stack-parsing, sliding window, intervals (including Meeting Rooms I & II), hashmap/heap, LRU Cache design, AST-flavoured trees, and graphs, plus 3 harder stretch follow-ups. LRUCache lives as its own stub class in the file — it’s a design problem, not a Solution method.

Where each set’s problems are explained

01

Arrays & Hashing

Sliding Window

Stack

Most-recent-first — matching, RPN, and the monotonic stack family.

Binary Search

Halve a monotonic space — including when it isn’t an array at all.
08

Heap

The extreme, repeatedly, on changing data — bounded size-k heaps and two-heap medians.
06

Linked Lists

Four maneuvers — reverse, dummy head, fast/slow, and the gap.
07

Binary Trees

The recursive contract — what to pass down, what to bubble up.
