Linked Lists

Four maneuvers solve almost everything. The whole game is manipulating next pointers without losing track of the list — and nearly every bug is a pointer you overwrote before you were done with it.

The core structure

A singly linked list node is just a value and a pointer to the next node:

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

The one habit: draw the pointers, save before you overwrite

The habit

Before writing any linked list code, draw three or four nodes as boxes with arrows and physically trace what each pointer points to after every line. The number one bug in this section is a.next = b clobbering the only reference you had to the old a.next.

nxt = curr.next   # save what you're about to lose
curr.next = prev  # now it's safe to overwrite
prev = curr       # walk forward
curr = nxt

That four-line dance is list reversal, and it’s the most reused block in the whole section. If you can write it without thinking, half the problems fall.

The 30-second mental check

AskReach for
Can the head itself change, move, or get removed?A dummy head in front, so you never special-case the first node. Merges and removals almost always want this.
Do I need the middle, a position relative to the end, or to detect a cycle?Two pointers — fast/slow for middle and cycles, or a fixed-gap leader/follower for “nth from the end.”
Am I about to overwrite a next I still need?Save it first (nxt = curr.next) before relinking. This is the reversal dance and the source of nearly every bug.

Maneuver 1 — reverse in place

def reverse(head):
    prev = None
    curr = head
    while curr:
        nxt = curr.next
        curr.next = prev
        prev = curr
        curr = nxt
    return prev            # the new head

Maneuver 2 — the dummy head

When the head itself might change or get removed, allocate a fake node in front so you never special-case “what if it’s the first node.” Return dummy.next at the end.

dummy = ListNode(0, head)
# ... build off `dummy` ...
return dummy.next

Maneuver 3 — fast & slow pointers (Floyd’s)

Advance one pointer two steps for every one step of the other. Fast reaches the end when slow is at the middle; and if there’s a cycle, fast eventually laps slow and they meet. This one trick powers cycle detection, finding the middle, and the duplicate-number problem.

slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
    if slow is fast:
        break            # cycle detected
# no cycle: slow is now at the middle
Find the Duplicate Number — the sneaky one

Given n+1 integers in the range 1…n, treat the array as a linked list where i → nums[i]. Because some value repeats, two indices point at the same successor — which is exactly a cycle, and the duplicate is the cycle’s entrance. Run Floyd’s, then phase 2. O(n) time, O(1) space, input unmodified.

Maneuver 4 — the two-pointer gap

Advance one pointer n steps ahead, then move both together. When the leader hits the end, the follower sits exactly n from the end — one pass, no length calculation.

Composing maneuvers: Reorder List

Reorder List looks intimidating and is actually three primitives back to back. Decomposing it is the whole exercise.

Copy List with Random Pointer — the two-pass map

The difficulty is that a random pointer may target a node you haven’t created yet. Two passes solve it: create every node first, then wire the pointers once every target exists.

LRU Cache — hashmap plus doubly linked list

A mini design problem, and a genuinely good one: it exists to make you notice that neither structure alone can do the job.

Suggested order to attack them

  1. Reverse Linked ListDrill the four-line dance until it’s automatic. Then write it recursively too.
  2. Merge Two Sorted ListsLearn the dummy head. Attach the remaining tail rather than looping to the end.
  3. Linked List CycleLearn fast & slow, and be able to argue why they must meet.
  4. Reorder ListFirst combo: middle + reverse + merge. Remember to cut the first half’s tail.
  5. Remove Nth Node From End of ListTwo-pointer gap + dummy, in a single pass.
  6. Copy List with Random PointerHashmap old→new in two passes; mention the O(1)-space interleaving follow-up.
  7. Add Two NumbersBuild-as-you-go with carry. Don’t forget the final carry after both lists end.
  8. Find the Duplicate NumberFloyd’s applied to an array — the sneaky one. Phase 2 finds the cycle entrance.
  9. Merge K Sorted ListsHeap of (val, i, node), or divide-and-conquer over pairwise merges. Both are O(N log k).
  10. Reverse Nodes in K-GroupThe reversal dance on windows, with careful reconnection at each boundary.
  11. LRU CacheHashmap + doubly linked list. Use sentinel head/tail nodes and factor out _remove / _insert.

By the time you reach #9–11, the reversal dance and the dummy-head reflex from the first two problems will make the boss fights feel like assembly rather than invention.

Traps

Trap 1 — returning head after reversing

After the loop, head is the tail of the reversed list. Return prev.

Trap 2 — the missing null guard in fast/slow

while fast and fast.next — both conditions, in that order. fast.next.next explodes otherwise, and Python’s short-circuit ordering is what saves you.

Trap 3 — forgetting to cut the tail

In Reorder List, if the first half still points into the second, the merged list contains a cycle and the loop never terminates.

Trap 4 — dropping the final carry

In Add Two Numbers, [9] + [1] produces [0, 1]. Loop while l1 or l2 or carry, not just while the lists last.

Trap 5 — comparing nodes with ==

Use is for identity (slow is fast). == works by default too, but says the wrong thing and breaks if __eq__ is ever defined.

One practical tip

When you’re stuck, use paper

Draw the list with 4–5 nodes and step a real pen through your pointer moves, one line at a time. Linked list bugs are almost never logic errors — they’re a pointer you overwrote before you were done with it, and you’ll see it instantly on paper long before a debugger would show you.
