When a heap is the answer

A heap is the data structure you reach for whenever the phrase “the k-th largest,” “the smallest so far,” “the most frequent,” or “the median as data streams in” shows up.

It answers one question extremely fast — what’s the minimum (or maximum) element right now? — in O(log n) per insert/remove, without keeping the whole collection sorted. The entire section is about training yourself to hear those trigger phrases and reach for a heap instead of re-sorting an array every time the data changes.

There’s no custom node class to learn; in Python a heap is just a list you only ever touch through heapq.

What a heap actually is

The core tool: heapq on a plain list

Python’s heapq gives you a min-heap built on an ordinary list — the smallest element is always at index 0:

import heapq
h = []
heapq.heappush(h, 5)         # add — O(log n)
heapq.heappush(h, 1)
smallest = h[0]              # peek the min — O(1), does not remove
x = heapq.heappop(h)         # remove & return the min — O(log n)
heapq.heapify(nums)          # turn an existing list into a heap in-place — O(n)

Two idioms you’ll use constantly:

Max-heap by negating

heapq.heappush(h, -x)
largest = -heapq.heappop(h)

heapq is min-only, so to pop the largest, push the negation and negate again on the way out. Say “I’m simulating a max-heap by negating” out loud — it reads as deliberate rather than confusing.

Priority by tuple

heapq.heappush(h, (dist, point))
heapq.heappush(h, (-count, task))

The heap orders by the first element, ties broken by the next. This is how you sort points by distance, tasks by count, tweets by timestamp.

The tuple-comparison crash

If two tuples tie on the first element, Python compares the second. When that second element is a custom object with no __lt__, you get TypeError: '<' not supported. Insert a unique tiebreaker in the middle: (priority, counter, obj). This bites in Merge K Sorted Lists constantly.

The one habit: do I need the extreme repeatedly, as the data changes?

The habit

“Am I going to need the min/max over and over, while the set of elements keeps shifting under me?”

If you needed the extreme element once, you’d just call max(). The heap earns its keep only when you need it repeatedly on a changing collection — pull the smallest, add two more, pull the smallest again. That’s the tell.

The bounded size-k heap — the sharpest version of the instinct

Instead of a max-heap of everything, keep a min-heap of size k. Its root is the k-th largest, and every time a new element beats the root you pop the root and push the newcomer — the heap never grows past k.

import heapq
def kth_largest(nums, k):
    h = []
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)     # drop the smallest — keep only the top k
    return h[0]                  # the k-th largest is the min of the top k

The pattern families

Repeated extract-and-reinsert

Some problems repeatedly pull the top one or two elements, transform them, and push a result back. Last Stone Weight is the canonical shape — a max-heap you drain in a loop.

Heap of tuples for prioritised selection

When “priority” is a computed key, push (key, payload):

  • K Closest Points to Origin pushes (distance², point). Skip the square root — it’s monotonic, so it can’t change the ordering, and avoiding it removes a float-precision worry.
  • Task Scheduler pushes -count to always grab the most frequent remaining task.
  • Design Twitter merges each followee’s recent tweets by timestamp.

Greedy scheduling with a cooldown queue

Two heaps for a running median

Find Median from Data Stream keeps a max-heap of the smaller half and a min-heap of the larger half, balanced so their sizes differ by at most one. The median is then either the top of the larger heap or the average of both tops — O(log n) per insert, O(1) per query.

import heapq
class MedianFinder:
    def __init__(self):
        self.small = []          # max-heap (negated) — the lower half
        self.large = []          # min-heap          — the upper half

    def addNum(self, num):
        heapq.heappush(self.small, -num)
        # ordering repair: small's top must not exceed large's top
        heapq.heappush(self.large, -heapq.heappop(self.small))
        # balance repair: keep small the same size or one larger
        if len(self.large) > len(self.small):
            heapq.heappush(self.small, -heapq.heappop(self.large))

    def findMedian(self):
        if len(self.small) > len(self.large):
            return -self.small[0]
        return (-self.small[0] + self.large[0]) / 2

Suggested order to attack them

  1. Kth Largest Element in a StreamThe size-k heap idea in its simplest design form.
  2. Last Stone WeightMax-heap via negation, drain in a loop. Use heapify, not n pushes.
  3. K Closest Points to OriginHeap of (distance², point) tuples. Skip the square root and say why.
  4. Kth Largest Element in an ArrayBounded size-k heap on a static array. Compare against Quickselect’s O(n) average.
  5. Task SchedulerHeap + cooldown; greedy scheduling. There’s also a neat O(n) math formula worth knowing.
  6. Design TwitterHeap-merge inside a larger design problem. Only merge the k most recent per followee.
  7. Find Median from Data StreamThe boss: two balanced heaps, two invariants repaired on every insert.

Do problems 1 and 4 close together — they’re the same size-k heap idea, one arriving as a stream and one over a fixed array, and seeing them side by side cements when the bounded heap beats a full sort. By the time you reach Find Median, the “a heap gives me the extreme in O(log n)” reflex will be automatic, and the only new idea is running two of them.

Traps

Trap 1 — forgetting to negate on the way out

With a negated max-heap, heappop returns a negative number. Negate again. Half of all “my answer is inverted” bugs are this.

Trap 2 — heappush in a loop instead of heapify

Building a heap from an existing list is O(n) with heapify and O(n log n) with n pushes. Free win, and interviewers notice.

Trap 3 — assuming the list is sorted

A heap list is not sorted. Only h[0] is meaningful; h[1] tells you nothing useful. Never print a heap and reason about the order.

Trap 4 — mutating a value already inside a heap

Changing an element’s priority in place breaks the heap invariant silently. Either push a new entry and lazily skip stale ones on pop, or use a structure that supports decrease-key.

One practical tip

Name the root before you code

Write a one-line comment naming your heap and what its root means — e.g. # min-heap of the k largest seen; root == the k-th largest. Committing to whether it’s a min- or max-heap, whether you’re negating, and what the root represents is what turns “I’ll use a heap somewhere” into a correct solution.
