Graphs don’t have one shape, they have three

Unlike trees, a graph arrives in one of a few representations, and half the battle is recognising which one you got.

# 1. Grid (implicit graph): each cell is a node, neighbors are up/down/left/right
grid = [["1","1","0"], ["1","0","0"], ["0","0","1"]]

# 2. Adjacency list: node -> list of neighbors (build this from an edge list)
from collections import defaultdict
adj = defaultdict(list)
for u, v in edges:      # undirected: add both directions
    adj[u].append(v)
    adj[v].append(u)

# 3. Node object (like Clone Graph)
class Node:
    def __init__(self, val=0, neighbors=None):
        self.val = val
        self.neighbors = neighbors if neighbors is not None else []

The one habit: have I been here before?

The one thing that separates a graph traversal from a tree traversal is cycles. Trees can’t revisit a node; graphs can, and if you don’t guard against it you’ll loop forever.

The habit

“How am I marking a node as visited, and where in the code do I mark it?”

You have two tools:

  • A visited set (or seen dict) — the general answer, works everywhere.
  • Mutating the input in place — on grids you can often overwrite a visited "1" with "0" (or "#") instead of carrying a set. Cheaper, but destroys the input, so only do it when the problem lets you.

Traversal patterns — know these cold

DFS flood fill on a grid

def dfs(r, c):
    if (r < 0 or r >= rows or c < 0 or c >= cols
            or grid[r][c] != "1"):
        return
    grid[r][c] = "0"                 # mark visited by mutating
    dfs(r + 1, c); dfs(r - 1, c)
    dfs(r, c + 1); dfs(r, c - 1)

BFS on a grid — and the multi-source trick

from collections import deque
q = deque(sources)                   # can seed with MANY starts at once
while q:
    for _ in range(len(q)):          # one "minute"/level at a time
        r, c = q.popleft()
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if in_bounds(nr, nc) and (nr, nc) not in visited:
                visited.add((nr, nc))     # mark on ENQUEUE
                q.append((nr, nc))
    time += 1

The border-inward trick

Pacific Atlantic Water Flow and Surrounded Regions both flip from hard to easy with one reversal of perspective.

Topological sort (Kahn’s BFS on in-degrees)

from collections import defaultdict, deque
indegree = {n: 0 for n in range(numCourses)}
adj = defaultdict(list)
for course, pre in prerequisites:
    adj[pre].append(course)
    indegree[course] += 1

q = deque([n for n in indegree if indegree[n] == 0])
order = []
while q:
    n = q.popleft()
    order.append(n)
    for nxt in adj[n]:
        indegree[nxt] -= 1
        if indegree[nxt] == 0:
            q.append(nxt)
# if len(order) < numCourses there was a cycle

Union-Find (Disjoint Set Union)

parent = list(range(n))
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]   # path compression
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return False                    # already connected -> cycle
    parent[ra] = rb
    return True
Graph Valid Tree, in one sentence

A graph is a tree iff it is connected, has exactly n − 1 edges, and has no cycle. Any two of those imply the third, so in practice you check edge count first (an O(1) early exit) and then run union-find, failing on the first union that returns False.

Word Ladder — BFS on an implicit graph

The graph is never given to you; you build neighbours on demand. And the way you generate them decides whether the solution passes.

Suggested order to attack them

  1. Number of IslandsLearn the grid DFS flood fill. The guard clause handles bounds and visited together.
  2. Max Area of IslandSame flood fill, now returning a size instead of nothing.
  3. Clone GraphDFS/BFS with an old→new hashmap. The map doubles as the visited set.
  4. Islands and Treasure / Walls and GatesFirst multi-source BFS. Seed from every gate.
  5. Rotting OrangesMulti-source BFS, counting rounds. Remember to check for unreachable fresh oranges at the end.
  6. Pacific Atlantic Water FlowDFS inward from the borders; intersect the two reachable sets.
  7. Surrounded RegionsSame border trick, marking survivors then flipping the rest.
  8. Course ScheduleTopological sort as cycle detection. The leftover count is the answer.
  9. Course Schedule IISame code, now return the order.
  10. Graph Valid TreeUnion-find, or connectivity + edge count. Check edges == n-1 first.
  11. Number of Connected ComponentsUnion-find; start at n components and decrement on each successful union.
  12. Redundant ConnectionUnion-find; the first edge whose union returns False is the answer.
  13. Word LadderBFS on an implicit word graph. Use wildcard buckets, not pairwise comparison.

By #8 the DFS/BFS mechanics are automatic and you’re really just learning two new tools — topological sort and union-find — that the rest of the section reuses.

Traps

Trap 1 — marking visited too late

Mark on enqueue (BFS) or on entry (DFS), never after processing. Otherwise nodes enter the frontier multiple times.

Trap 2 — forgetting both directions in an undirected graph

adj[u].append(v) alone makes the graph directed. Half of “my traversal misses nodes” bugs are this line.

Trap 3 — using DFS for a shortest path

DFS finds a path, not the shortest. Any problem containing “minimum” or “fewest” on an unweighted graph wants BFS. (Weighted? That’s Dijkstra.)

Trap 4 — recursion depth on large grids

A 1000×1000 all-land grid means 10⁶ nested DFS calls. Python raises RecursionError. Say so, and offer the iterative stack version.

Trap 5 — reversed edges in topological sort

prerequisites[i] = [course, prereq] means the edge goes prereq → course. Build it the other way and you get a valid ordering of the wrong graph.

One practical tip

Three things, before any code

Write a one-line comment stating your node, your edge, and your visited strategy — e.g. # node = grid cell, edge = 4-way neighbor, visited = overwrite '1' with '0'. Getting those three straight up front is 80% of not writing an infinite loop.
