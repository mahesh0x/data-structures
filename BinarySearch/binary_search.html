Binary Search

Three lines of mechanics, and a deceptively hard section — because the real skill isn’t searching a sorted array. It’s recognising binary search when the array isn’t what you’re searching.

Why this section is harder than it looks

Binary search is the “throw away half the possibilities every step” pattern, and its whole value is turning O(n) into O(log n). The mechanics are trivial — a left, a right, a mid, and a decision to go one way or the other.

But this section is deceptively hard, because binary-searching a sorted array is problem one. The rest of the section is about recognising binary search when the input is a rotated array, a 2D grid, or an abstract range of answers like “eating speeds.” The pattern is the same three lines every time; the art is figuring out what you’re halving and which direction “the answer must be over there” points.

The one idea: can I rule out half with a single check?

The habit

“If I probe the middle of my range and look at it, can I prove the answer lies entirely in the left half or entirely in the right half?”

If you can make that proof, you can binary search — even if the input isn’t a plainly sorted array. That’s the leap this section is built to teach.

  • On a rotated array, the trick is that one side of mid is always sorted, so you can test whether the target falls in that sorted side and eliminate the other.
  • On Koko Eating Bananas, you’re not searching the array at all — you’re binary-searching over the answer (possible eating speeds 1…max), and the “can she finish in time at this speed?” check is monotonic (faster is always at-least-as-good).
The general statement

When the space of possible answers is monotonic — some threshold splits “no” from “yes” and never flips back — you can binary search it, with no array in sight.

The core template and the boundary trap

left, right = 0, len(nums) - 1        # inclusive bounds
while left <= right:                  # <= because both ends are valid candidates
    mid = (left + right) // 2
    if nums[mid] == target:
        return mid
    elif nums[mid] < target:
        left = mid + 1                # answer is strictly right of mid
    else:
        right = mid - 1               # answer is strictly left of mid
return -1

Two things cause 90% of binary-search bugs, so decide them before you type:

  1. Are your bounds inclusive or exclusive? Pick left <= right with right = len-1 (inclusive) and stick to it. Mixing conventions is how you get off-by-ones and infinite loops.
  2. Does mid move to mid+1/mid-1, or stay at mid? Whenever a branch keeps mid as a candidate (common in “find the minimum / find the boundary” problems), make sure the range still shrinks each iteration, or you loop forever.

The pattern families

1. Classic search on a sorted array

Binary Search, and Search a 2D Matrix — where every row is sorted and each row’s first element exceeds the previous row’s last. That property means the grid is one flat sorted array; you just need index arithmetic to pretend.

2. Binary search on the answer space

Koko Eating Bananas. You don’t search the piles; you search speeds 1…max(piles). For a candidate speed, compute hours needed; “fits in h hours” is monotonic in speed, so binary search for the smallest speed that fits.

import math
def minEatingSpeed(piles, h):
    def hours_needed(speed):
        return sum(math.ceil(p / speed) for p in piles)

    left, right = 1, max(piles)
    while left < right:
        mid = (left + right) // 2
        if hours_needed(mid) <= h:        # this speed works — try slower
            right = mid                   # keep mid: it might be the answer
        else:                             # too slow — must go faster
            left = mid + 1
    return left                           # smallest speed that fits

3. Rotated / partially-sorted arrays

Find Minimum in Rotated Sorted Array and Search in Rotated Sorted Array. The invariant that saves you: at any mid, either [left..mid] or [mid..right] is fully sorted. Determine which, check whether your target lies inside that sorted half’s range, and recurse into the correct side.

def search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        if nums[left] <= nums[mid]:              # left half is sorted
            if nums[left] <= target < nums[mid]:
                right = mid - 1
            else:
                left = mid + 1
        else:                                    # right half is sorted
            if nums[mid] < target <= nums[right]:
                left = mid + 1
            else:
                right = mid - 1
    return -1

Find Minimum is the same invariant with a simpler objective — you don’t need a target at all, only “which side holds the wrap point”:

def findMin(nums):
    left, right = 0, len(nums) - 1
    while left < right:
        mid = (left + right) // 2
        if nums[mid] > nums[right]:   # the drop is to the right of mid
            left = mid + 1
        else:                         # mid could itself be the minimum
            right = mid
    return nums[left]
Why compare against right, not left?

Comparing nums[mid] with nums[right] is unambiguous: if nums[mid] > nums[right], the wrap must lie strictly after mid. Comparing against nums[left] needs an extra case for the already-sorted (zero-rotation) array. Small choice, meaningfully less code.

4. Binary search as a component in a design problem

Time Based Key-Value Store. Each key stores an append-only, timestamp-sorted list of (timestamp, value); get(key, t) binary-searches that list for the largest timestamp <= t. This is the “floor” variant — you’re not looking for an exact match, you’re looking for the best candidate at or below a bound.

class TimeMap:
    def __init__(self):
        self.store = {}                       # key -> list of [timestamp, value], ascending

    def set(self, key, value, timestamp):
        self.store.setdefault(key, []).append([timestamp, value])

    def get(self, key, timestamp):
        entries = self.store.get(key, [])
        res = ""
        left, right = 0, len(entries) - 1
        while left <= right:
            mid = (left + right) // 2
            if entries[mid][0] <= timestamp:
                res = entries[mid][1]         # a valid candidate — remember it
                left = mid + 1                # but try for a later one
            else:
                right = mid - 1
        return res
The floor-search idiom

“Record the candidate, then keep searching in the promising direction” is a clean way to write any boundary search without fighting the loop conventions. It costs one extra variable and removes a whole class of off-by-one bugs.

5. Partition search — the boss

Median of Two Sorted Arrays. Famously hard, and the payoff for everything above: instead of searching for a value, you binary-search for a partition point in the smaller array such that everything left of the combined partition is <= everything to its right. The median falls out of the four boundary elements.

Suggested order to attack them

  1. Binary SearchNail the template and the boundary conventions. Write it from memory until it’s reflexive.
  2. Search a 2D MatrixSame template, flattened index. divmod(mid, cols).
  3. Koko Eating BananasThe mental shift: search the answer space, not the array. State the monotonic predicate out loud.
  4. Find Minimum in Rotated Sorted ArrayLearn the “which half is sorted” test with the simplest possible objective.
  5. Search in Rotated Sorted ArrayThe same reasoning aimed at a target instead of the minimum. Do this back-to-back with #4.
  6. Time Based Key-Value StoreBinary search as a component. Practise the floor-search idiom.
  7. Median of Two Sorted ArraysThe hardest — partition search. Always binary-search the shorter array, and use ±∞ sentinels.

Do problems 4 and 5 back-to-back: Find Minimum teaches the “one half is always sorted” invariant with a simpler objective, and Search in Rotated is that exact same reasoning aimed at a target.

Traps

Trap 1 — the infinite loop

A branch that assigns left = mid with mid rounded down never terminates when right - left == 1. Either round mid up, or make both branches exclude mid.

Trap 2 — mixed bound conventions

right = len(nums) with while left <= right will index out of range. Pick one convention per problem and keep it.

Trap 3 — assuming the answer space is monotonic without checking

Before search-on-answer, actually verify: if speed s works, does every s+1 work? If the predicate can flip back, binary search silently returns garbage.

Trap 4 — searching the longer array in Median

Binary-search the shorter array. Otherwise the derived cut in the other array can go negative or past the end, and you’ll be clamping indices forever.

A note on (left + right) // 2

In C++/Java this can overflow, and left + (right - left) // 2 is the standard fix. Python integers are arbitrary-precision so it can’t overflow here — but knowing why the other form exists is a good thing to mention.

One practical tip

Write these two comments first

# search space: [what left and right represent]
# I move left/right when: [the proof that the answer is on the other side]

Especially for the answer-space and rotated problems, being explicit about what you’re halving and why the eliminated half can’t contain the answer is the difference between a clean solution and an infinite loop.
