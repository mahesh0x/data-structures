Why this small section matters so much

Two Pointers is a small section — five problems — but it’s one of the highest-leverage patterns in the whole list, because it’s the trick that turns an O(n²) scan into an O(n) sweep without spending any extra memory. That last clause is what distinguishes it from Arrays & Hashing: hashing buys speed with space, two pointers buys speed with structure.

Nearly every two-pointer problem is the same physical picture: two indices walking a line. Once the decision rule is clear in your head, the code writes itself. The hard part is never the loop — it’s the argument for why the loop is correct.

The one idea: prove the move is safe

The habit

“At each step, based on comparing the two ends, which pointer should I advance — and why is it safe to throw away the element I’m moving past?”

That word safe is the whole pattern. A two-pointer solution works only because every time you move a pointer inward, you can prove you’re not skipping a better answer.

  • In Container With Most Water you move the shorter wall in, because the shorter wall is the bottleneck — keeping it and shrinking the width can never help.
  • In sorted Two Sum you move left up when the sum is too small, because every pair using the current left with a smaller partner is also too small.

If you can articulate why moving past this element loses nothing, you have the solution. If you can’t, two pointers probably isn’t the right tool — and that’s a genuinely useful negative signal, not a failure.

The counting argument

A converging two-pointer loop runs at most n iterations, because every iteration moves one pointer one step and the two pointers start n apart. That’s the entire O(n) proof, and it’s worth saying out loud in an interview — it takes four seconds and shows you know why the loop terminates.

The two flavors

Converging template

left, right = 0, len(arr) - 1
while left < right:
    if condition(arr[left], arr[right]):
        left += 1
    else:
        right -= 1

Anchor + sweep template

arr.sort()
for i in range(len(arr)):
    left, right = i + 1, len(arr) - 1
    while left < right:
        ...            # converging pair

Walkthrough: Valid Palindrome

The gentlest possible converging pair — no arithmetic, no sorting, just symmetry. The string’s order is the structure.

def isPalindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True

Walkthrough: Two Sum II — the cleanest “why moving is safe”

This is the problem to fully understand, because its safety argument is the template for every other one in the section.

Techniques you’ll reuse

Skip duplicates by advancing while equal

In problems that must return unique results (3Sum), after you record an answer, slide the pointer past any repeats so you don’t emit the same triple twice:

while left < right and nums[left] == nums[left + 1]:
    left += 1

Sort first when order doesn’t matter

3Sum and sorted Two Sum both depend on sorted input. If the problem returns values (not original indices) and asks for pairs/triples summing to a target, sorting is usually step one — it’s what unlocks the converging sweep. The cost is O(n log n), which is still dominated by the O(n²) outer loop in 3Sum, so it’s free.

When sorting is NOT allowed

If the problem wants original indices (plain Two Sum), you cannot sort — sorting destroys the indices. That’s exactly why plain Two Sum is a hash-map problem and Two Sum II is a two-pointer problem. Same question, different constraint, completely different tool.

Track a running best as the window changes

Container With Most Water and Trapping Rain Water both walk two pointers inward while keeping a max/accumulated total. The area or water at each step is a function of the two current heights and the gap between the pointers.

3Sum — composing the two flavours

3Sum is Two Sum II with a hat on. Sort, fix one element with an outer loop, then run a converging pair on everything to its right. The only genuinely fiddly part is deduplication, and it has to happen in three places.

def threeSum(nums):
    nums.sort()
    res = []
    for i in range(len(nums) - 2):
        if nums[i] > 0:                       # sorted: no way to reach 0 from here
            break
        if i > 0 and nums[i] == nums[i - 1]:  # dedup checkpoint 1
            continue
        left, right = i + 1, len(nums) - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                res.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:   # checkpoint 2
                    left += 1
                while left < right and nums[right] == nums[right + 1]: # checkpoint 3
                    right -= 1
    return res

Container With Most Water — move the limiting side

Area between two walls is min(h[left], h[right]) × (right - left). Start at the widest possible pair and shrink. The decision rule is one line, but the proof is what makes it click.

def maxArea(height):
    left, right = 0, len(height) - 1
    best = 0
    while left < right:
        best = max(best, min(height[left], height[right]) * (right - left))
        if height[left] < height[right]:
            left += 1          # the short wall can never do better — retire it
        else:
            right -= 1
    return best

Trapping Rain Water — the boss

The hardest to derive, and the one worth spending real time on. It rests on a single per-column formula:

The formula

Water sitting above column i is min(max_left[i], max_right[i]) - height[i].
A column is a bathtub whose two walls are the tallest bar anywhere to its left and the tallest bar anywhere to its right. The shorter of those two walls is where the water spills over.

def trap(height):
    if not height:
        return 0
    left, right = 0, len(height) - 1
    left_max, right_max = height[left], height[right]
    water = 0
    while left < right:
        if left_max < right_max:
            left += 1
            left_max = max(left_max, height[left])
            water += left_max - height[left]      # cannot be negative — left_max just updated
        else:
            right -= 1
            right_max = max(right_max, height[right])
            water += right_max - height[right]
    return water

Suggested order to attack them

  1. Valid PalindromeConverging-pointer muscle memory with no math. Get the skip-guard right.
  2. Two Sum II — Input Array Is SortedThe canonical “which side moves” decision, and the safety proof you’ll reuse everywhere.
  3. 3SumCompose Two Sum II inside an outer loop, plus duplicate skipping in three places.
  4. Container With Most WaterIntroduces the “move the limiting side” idea on areas. Say the dominance argument out loud.
  5. Trapping Rain WaterThe boss: two-sided maxes and move-the-smaller-side. Derive the O(n)-space version first, then compress it.

By the time you reach Trapping Rain Water, the “move the limiting side, and prove it’s safe” reasoning from Container With Most Water will make the water-bounding argument click instead of feeling arbitrary.

Traps

Trap 1 — left <= right vs left < right

For pair problems you want <: an element must not pair with itself. For problems where the two pointers can legitimately land on the same element, you want <=. Decide which before you type, and never change it mid-debug.

Trap 2 — forgetting the guard inside skip loops

while not s[left].isalnum(): left += 1 walks off the end of "...". Always while left < right and ....

Trap 3 — deduping in only one place in 3Sum

Skipping duplicate anchors is necessary but not sufficient. [-2,0,0,2,2] will emit [-2,0,2] twice unless you also skip after recording a hit.

Trap 4 — sorting when indices matter

If the answer is a list of original indices, sorting destroys the answer. Reach for a hash map instead (see Arrays & Hashing).

One practical tip

Do this before coding

Write your move rule as an if/else in plain English, in a comment — e.g. # sum < target: left++ (need bigger); sum > target: right-- (need smaller). If you can’t fill in the why after each branch, you don’t yet understand the problem well enough to code it.
