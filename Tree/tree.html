The core structure

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

Everything you do with trees comes down to: look at a node, decide what to do with its value, and recurse into left and right. That’s it. The entire difficulty of tree problems is figuring out what information to pass down and what information to bubble back up.

The one habit: the recursive contract

The habit

Before writing any tree code, answer one question: “If I had the answer for the left subtree and the right subtree, how would I combine them to get the answer for this node?”

Then trust that the recursion will handle the subtrees for you. This is the leap of faith — don’t try to trace through the whole call stack in your head. Write the base case (usually if not root: return ...), write the combine step, done.

This single habit solves probably 80% of NeetCode’s tree section. And it works because of the structural fact in the figure above: a subtree is the same kind of object as the tree, so a function that is correct for the whole tree is automatically correct for every subtree.

Traversal patterns — know these cold

BFS — level by level

Whenever a problem says “level,” “row,” or “rightmost/leftmost at each depth,” think BFS with a queue immediately.

from collections import deque
def bfs(root):
    if not root: return
    q = deque([root])
    while q:
        level_size = len(q)
        for _ in range(level_size):
            node = q.popleft()
            # process node
            if node.left: q.append(node.left)
            if node.right: q.append(node.right)

Top-down vs. bottom-up — the real pattern to internalise

Bottom-up: Maximum Depth

def maxDepth(root):
    if not root: return 0
    return 1 + max(maxDepth(root.left),
                   maxDepth(root.right))

This exact shape — return 0 on null, combine children with +1/max/min — reappears in Maximum Depth, Balanced, Diameter, Count Good Nodes, and Max Path Sum.

Top-down: Path Sum

def hasPathSum(root, target):
    if not root: return False
    if not root.left and not root.right:
        return root.val == target
    rem = target - root.val
    return (hasPathSum(root.left, rem)
         or hasPathSum(root.right, rem))

The remaining target is context handed downward. Nothing is combined on the way back up except a boolean.

Early termination: bubbling the answer up

Group 3 problems below lean on this. The moment you find the answer (or a violation), return it straight up the call stack so the remaining recursion unwinds without visiting the rest of the tree.

BSTs: use the ordering, don’t just traverse

A BST guarantees every value in the left subtree is smaller and every value in the right subtree is larger. That’s stronger than “left child < parent < right child,” and confusing the two is the classic Validate BST bug.

The BST speed-up you should always mention

Lowest Common Ancestor of a BST doesn’t need a full DFS. Walk down from the root: if both targets are smaller, go left; if both are larger, go right; the first node that sits between them (or equals one of them) is the LCA. O(h) instead of O(n), and about five lines.

Construction and serialization

Serialization is the same insight in reverse: usually a preorder DFS with explicit null markers, and deserialization replays that same order using an iterator or queue.

def serialize(root):
    out = []
    def dfs(node):
        if not node:
            out.append("#"); return          # explicit null marker — essential
        out.append(str(node.val))
        dfs(node.left); dfs(node.right)
    dfs(root)
    return ",".join(out)

def deserialize(data):
    vals = iter(data.split(","))
    def build():
        v = next(vals)
        if v == "#":
            return None
        node = TreeNode(int(v))
        node.left = build(); node.right = build()   # same order as serialize
        return node
    return build()
Why the null markers are non-negotiable

Without them, preorder alone is ambiguous — many different trees produce the same sequence. The # placeholders restore the structural information that flattening threw away.

Binary Tree Maximum Path Sum — the boss

The distinction that trips people up constantly: a path that must go through a node vs. a path that can be anywhere in the tree. Max Path Sum needs both at once, and the resolution is that the function returns one thing while a side variable records another.

def maxPathSum(root):
    best = float("-inf")
    def gain(node):
        nonlocal best
        if not node:
            return 0
        left = max(gain(node.left), 0)          # negative branches are skipped
        right = max(gain(node.right), 0)
        best = max(best, node.val + left + right)   # RECORD: the bent path
        return node.val + max(left, right)          # RETURN: the one-way path
    gain(root)
    return best

Suggested order to attack them

  1. Invert Binary TreeGet the recursion muscle memory. Three lines.
  2. Maximum Depth of Binary TreeThe canonical bottom-up combine.
  3. Diameter of Binary TreeFirst taste of return-one-thing / record-another.
  4. Balanced Binary TreeReturn the height, or a sentinel like -1 to signal “already unbalanced” and short-circuit.
  5. Same Tree / Subtree of Another TreePaired — the second calls the first at every node.
  6. Binary Tree Level Order TraversalSwitch gears to BFS. Snapshot len(q).
  7. Binary Tree Right Side ViewSame queue, record the last node of each level.
  8. Count Good Nodes in Binary TreeMax-so-far passed down, count returned up.
  9. Validate Binary Search TreeInherited (low, high) bounds — not parent comparisons.
  10. Kth Smallest Element in a BSTInorder with a counter and an early return.
  11. Lowest Common Ancestor of a BSTUse the ordering to walk down in O(h). Don’t write a general-tree DFS.
  12. Construct Binary Tree from Preorder and InorderIndex map + ranges, not slicing, to keep it O(n).
  13. Binary Tree Maximum Path SumReturn the one-way path, record the bent one, clamp negatives at zero.
  14. Serialize and Deserialize Binary TreePreorder with explicit null markers; deserialize replays the identical order.

That’s 15 problems across 14 steps — Same Tree and Subtree of Another Tree are paired in step 5 since they’re the same move. By the time you hit #13–14, the earlier ones will have made the “return value + combine” and “helper function with extra state” moves feel automatic.

Traps

Trap 1 — validating a BST against the parent only

A node must satisfy every ancestor’s constraint, not just its parent’s. Pass a (low, high) window down.

Trap 2 — confusing height with depth (and off-by-one)

Decide whether your function counts nodes or edges and write it in the docstring. Diameter counts edges; Maximum Depth counts nodes. Mixing them is a silent off-by-one.

Trap 3 — forgetting level_size in BFS

Without snapshotting len(q) before the inner loop, levels bleed into each other.

Trap 4 — slicing in tree construction

build(preorder[1:i+1], inorder[:i]) is O(n²) time and O(n²) memory. Pass index ranges instead.

Trap 5 — recursion depth

A degenerate (linked-list-shaped) tree of 10⁵ nodes will blow Python’s default recursion limit. Mention it; offer the iterative traversal if pressed.

One practical tip

State your contract before you code

When you’re stuck on a new tree problem, explicitly write out in a comment what your function returns and what it means before writing any code — e.g. # returns: height of subtree rooted at node, or -1 if not balanced. That one sentence usually reveals the solution shape immediately.
