Why this section comes first

Arrays & Hashing is the first section in NeetCode 150 for a reason: it’s where you build the reflex that carries the entire list — “can I trade memory for time by remembering what I’ve already seen?” Almost every problem here is really a question about which lookup structure to reach for, and once that clicks, half the work is done before you write a loop.

Notice what’s absent from this section: there is no custom data structure to learn. No node class, no tree, no heap. The whole section is about wielding Python’s built-in set, dict, and list well. That’s deliberate — the pedagogical payload isn’t a structure, it’s a move. Every later section (Two Pointers, Sliding Window, Graphs, Heap) quietly assumes you’ll reach for a hash map without thinking whenever the problem needs an O(1) “have I seen this?”

So the goal for this section is not “solve nine problems.” It’s to make one particular thought automatic, so that later, when you’re neck-deep in Course Schedule or Word Ladder, the hash-map part of the solution costs you zero thinking budget.

The one idea: turn the inner loop into a lookup

Before writing any array/hashing code, ask one question:

The habit

“As I walk through this array once, what do I need to remember about what I’ve already passed, so that when I reach the current element I can answer in O(1)?”

That “what do I need to remember” is almost always a set (membership: have I seen this value?) or a dict (mapping: what index / count / group does this value belong to?).

Here is the shape of the transformation, and it is worth staring at until it feels obvious. The brute-force version of nearly every problem in this section is a nested double loop — O(n²) — and the hashing version replaces the inner loop with a single O(1) lookup into a structure you built on the way in.

How a hash table actually delivers O(1)

It’s worth understanding why the lookup is free, because it explains the two constraints you’ll bump into (keys must be hashable; worst case isn’t really O(1)).

Two practical consequences

1. Keys must be hashable (immutable). A list can’t be a dict key because it can change, which would change its hash. That’s exactly why Group Anagrams uses tuple(sorted(s)) and not sorted(s) — the tuple is frozen, the list is not.

2. Insertion order is preserved in Python 3.7+ dicts. Handy for problems where you want to read results back in the order you first met them, but never rely on it for correctness in an interview unless you say so out loud.

The 30-second mental check

When an arrays problem lands in front of you, ask which of these you need. Naming the structure and what its keys and values mean before writing a loop is most of the work.

Four built-ins do everything in this section. Know their costs cold — interviewers ask.

The one-line bug that costs the interview

Writing if x in my_list inside a loop. That’s an O(n) scan hiding inside what you think is an O(n) algorithm — you just wrote O(n²) and it looks like O(n). Convert to a set first, every single time.

Technique families

1. Counting with a dict

The workhorse. Build a frequency map in one pass, then read from it:

from collections import Counter
count = Counter(nums)          # {value: how many times}

# the manual version, if asked not to use Counter:
count = {}
for x in nums:
    count[x] = count.get(x, 0) + 1

Two strings are anagrams iff their Counters are equal — that’s the entire Valid Anagram problem, one line:

def isAnagram(s, t):
    return Counter(s) == Counter(t)

The interview-friendly version avoids the library and shows you understand the mechanism: build one counter from s, decrement it with t, and assert every count landed back on zero. If any count goes negative or any key is left over, they differ.

Say this out loud

“Sorting both strings also works and is O(n log n) with O(1) extra space; counting is O(n) time and O(k) space where k is the alphabet size. Which trade do you want?” That sentence alone demonstrates the thing the question is testing.

2. Complement lookup — the Two Sum move

Instead of searching for two things that combine to a target, fix one and look up the other one you’d need. This is the single most important pattern in the section, and it recurs for the rest of your life as an interviewee.

seen = {}                      # value -> index
for i, x in enumerate(nums):
    if target - x in seen:
        return [seen[target - x], i]
    seen[x] = i

The subtlety worth internalising: you build the map as you go, so each element only ever looks backward at what’s already stored. That’s why you don’t need a second pass, and why an element can never pair with itself — it isn’t in the map yet when it asks.

3. Canonical key / signature grouping

When you need to group items that are “the same” under some transformation, compute a key that is identical for all members of a group and bucket by it. The art is choosing the signature.

from collections import defaultdict
groups = defaultdict(list)
for s in strs:
    key = tuple(sorted(s))     # or a 26-length count tuple
    groups[key].append(s)
return list(groups.values())

4. Bucket sort by frequency

When a problem says “top k most frequent,” you don’t need a full sort or a heap. The insight is a bound: no value can appear more than len(nums) times, so counts live in a small known range — and anything in a small known range can be used as an array index instead of a sort key.

freq = [[] for _ in range(len(nums) + 1)]   # freq[c] = values that appear c times
for val, c in Counter(nums).items():
    freq[c].append(val)

res = []
for c in range(len(freq) - 1, 0, -1):       # walk from the high-count end
    for val in freq[c]:
        res.append(val)
        if len(res) == k:
            return res

5. Prefix / suffix passes

Some problems that look like they need a hash are actually solved by walking the array twice — once left-to-right accumulating a running result, once right-to-left — and combining. Product of Array Except Self is the canonical example, and it exists specifically to stop you reaching for the hash reflex on autopilot.

6. Set membership plus a “start of run” test

Longest Consecutive Sequence is the cleverest problem in the section, and its trick is a beautiful example of using a set for something other than deduplication. The naive approach — for each number, walk upward counting — is O(n²) because long runs get re-walked from every member. The fix is one guard clause:

nums_set = set(nums)
best = 0
for n in nums_set:
    if n - 1 in nums_set:      # not the start of a run -> skip entirely
        continue
    length = 1
    while n + length in nums_set:
        length += 1
    best = max(best, length)
return best

7. Hashing coordinates — Valid Sudoku

Valid Sudoku is deceptively simple once you see it as three simultaneous membership problems, all solvable in a single pass over the 81 cells. The only piece of real thinking is the box index.

8. Length-prefix encoding

Encode and Decode Strings is a design question wearing a string costume. The naive answer — join with a delimiter like "#" — breaks the moment a payload contains that delimiter. The fix is to make the encoding self-describing: prefix each string with its length, so the decoder never has to guess where a string ends.

Suggested order to attack them

  1. Contains DuplicateGet the set reflex. Solve it three ways (sort, set, length comparison) and be able to state the trade-offs.
  2. Valid AnagramGet the Counter reflex. Then redo it without Counter, using a plain dict and a decrement pass.
  3. Two SumThe complement lookup — the single most important pattern here. Do the one-pass version, not the two-pass one.
  4. Group AnagramsCanonical-key bucketing. Try both keys: tuple(sorted(s)) and a 26-length count tuple.
  5. Top K Frequent ElementsBucket sort by frequency. Note out loud that this beats both the heap and the sort.
  6. Encode and Decode StringsLength-prefix design. The interviewer is testing whether you spot the delimiter-collision bug unprompted.
  7. Product of Array Except SelfPrefix/suffix, no division. Push for the O(1)-extra-space version where the output array carries the prefix pass.
  8. Valid SudokuHashing rows, columns and boxes at once. The (r//3, c//3) key is the whole insight.
  9. Longest Consecutive SequenceSet + start-of-run trick — the cleverest one, saved for last. Be ready to prove why the nested loop is still O(n).

By the time you reach Longest Consecutive Sequence, the “trade memory for a lookup” instinct will be automatic, and its O(n) trick — only expand a run when you’re standing on its smallest element — will feel like a natural extension rather than a rabbit out of a hat.

Traps that cost people this section

Trap 1 — the hidden O(n) lookup

if x in some_list is a linear scan. In a loop, that’s O(n²) disguised as O(n). Convert to a set before the loop.

Trap 2 — unhashable keys

d[[1,2]] = x raises TypeError: unhashable type: 'list'. Use a tuple. Same reason a set of lists is impossible but a set of tuples is fine.

Trap 3 — mutating while iterating

for k in d: del d[k] raises RuntimeError. Iterate over list(d) or list(d.items()) if you plan to modify.

Trap 4 — counting the second string wrong

In Valid Anagram, if you decrement counts from t without checking for negatives or leftover keys, "aab" vs "abb" can slip through. Check the length first, then verify every count is zero.

Trap 5 — division in Product of Array Except Self

“Multiply everything, then divide by nums[i]” is banned by the problem and broken by zeros. If you catch yourself reaching for it, that’s the signal to do prefix/suffix.

One practical tip

Do this before every loop

Write a one-line comment naming the structure and what its keys and values mean — e.g. # count: letter -> how many times it appears in s. Committing to what the map holds before you build it is what turns a vague “I’ll use a dict somewhere” into an actual solution. It also gives the interviewer something to nod at while you type.
