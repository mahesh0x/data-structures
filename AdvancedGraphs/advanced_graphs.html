What changes from the Graphs section

If the Graphs section was about how to move through a graph (DFS/BFS), Advanced Graphs is about what to optimise while you move — the cheapest way to connect everything, the shortest weighted path, a valid ordering, an unbroken trail.

There are only six problems here, but each one is really a named classical algorithm in disguise. The implementations are short; the recognition is the hard part.

The core structure — weighted graphs and the heap

Almost everything here operates on a weighted adjacency list, and almost every shortest-path / MST algorithm reaches for a min-heap to always expand the cheapest option next.

from collections import defaultdict
import heapq

# weighted adjacency list: node -> list of (neighbor, weight)
adj = defaultdict(list)
for u, v, w in edges:
    adj[u].append((v, w))        # directed; add the reverse too if undirected

# the universal move: a min-heap keyed by cost-so-far
heap = [(0, start)]              # (cost, node)
while heap:
    cost, node = heapq.heappop(heap)   # always pull the cheapest frontier node
    ...
    heapq.heappush(heap, (cost + w, nxt))

heapq is a plain min-heap over tuples — it sorts by the first element, so you put the thing you want to minimise (distance, edge weight) first. That single pattern powers Dijkstra, Prim, and the “swim” problem.

The one habit: which classical algorithm is this?

The habit

“Am I minimising a total path cost, a total connection cost, finding an ordering, or tracing an unbroken trail?”

Dijkstra — single-source shortest path

def dijkstra(adj, start, n):
    dist = {}
    heap = [(0, start)]
    while heap:
        d, node = heapq.heappop(heap)
        if node in dist:            # already finalized (lazy deletion)
            continue
        dist[node] = d
        for nxt, w in adj[node]:
            if nxt not in dist:
                heapq.heappush(heap, (d + w, nxt))
    return dist
Network Delay Time, in one line

The time for a signal to reach all nodes is max(dist.values()) — the slowest of the finalised distances — or -1 if len(dist) < n, meaning some node was never reached.

Swim in Rising Water — a Dijkstra variant

The one change that makes it interesting: a path’s cost is the maximum elevation along it, not the sum. Everything else is identical.

Minimum Spanning Tree — Prim vs. Kruskal

Prim’s

def prim(adj, n):
    visited = set()
    heap = [(0, 0)]        # (edge_weight, node)
    total = 0
    while heap and len(visited) < n:
        w, node = heapq.heappop(heap)
        if node in visited:
            continue
        visited.add(node)
        total += w
        for nxt, wt in adj[node]:
            if nxt not in visited:
                heapq.heappush(heap, (wt, nxt))
    return total

Kruskal’s

edges.sort(key=lambda e: e[2])   # by weight
total = 0
for u, v, w in edges:
    if union(u, v):    # False if already connected
        total += w
return total

Needs the union-find from the Graphs section. Better when the graph is sparse or the edges arrive pre-sorted.

Bellman-Ford — shortest path with a hop limit

prices = [float("inf")] * n
prices[src] = 0
for _ in range(k + 1):              # at most k stops = k+1 edges
    tmp = prices[:]                 # freeze this round's values
    for u, v, w in flights:
        if prices[u] + w < tmp[v]:
            tmp[v] = prices[u] + w
    prices = tmp
return -1 if prices[dst] == float("inf") else prices[dst]

Hierholzer’s algorithm — Eulerian path

Reconstruct Itinerary: use every ticket exactly once, choosing the lexicographically smallest route. The algorithm is short and its correctness is genuinely non-obvious.

def hierholzer(adj, start):         # adj[node] = sorted deque of destinations
    route = []
    stack = [start]
    while stack:
        while adj[stack[-1]]:
            stack.append(adj[stack[-1]].popleft())
        route.append(stack.pop())
    return route[::-1]

Alien Dictionary — topological sort under uncertainty

The algorithm is a plain topological sort. The hard part is constructing the graph from a word list.

Suggested order to attack them

  1. Network Delay TimeThe cleanest Dijkstra — get the min-heap template solid, including lazy deletion.
  2. Min Cost to Connect All PointsPrim’s MST — same heap shape, edge-weight key instead of cumulative cost.
  3. Swim in Rising WaterDijkstra variant — path cost is a max, not a sum. One-character change to the combine step.
  4. Cheapest Flights Within K StopsBellman-Ford — and understand why the K limit breaks plain Dijkstra.
  5. Reconstruct ItineraryEulerian path / Hierholzer’s — a new shape entirely. Post-order, then reverse.
  6. Alien Dictionary / Foreign DictionaryTopological sort; deriving the edges (and the prefix edge case) is the hard part.

Do Network Delay Time first even though NeetCode lists Reconstruct Itinerary first — Dijkstra is the foundational template three of these six reuse, and it’s the cleanest place to build the heap muscle memory. Save Alien Dictionary for last; the algorithm is a plain topo sort, but constructing the graph from the word list is the trickiest reasoning in the section.

Traps

Trap 1 — Dijkstra with negative weights

The greedy finalisation is invalid. Use Bellman-Ford. If asked “what if edges can be negative?”, this is the expected answer.

Trap 2 — forgetting the frozen copy in Bellman-Ford

Without tmp = prices[:], one round can chain multiple hops and quietly exceed the K limit.

Trap 3 — using cumulative distance as Prim’s heap key

Prim minimises the next edge, not the distance from the start. Using Dijkstra’s key builds a shortest-path tree, which is a different (and usually more expensive) tree.

Trap 4 — missing the prefix case in Alien Dictionary

["abcd", "ab"] must return "". Check it explicitly before looking for a differing character.

Trap 5 — comparing beyond the first difference

Each adjacent word pair gives at most one constraint. Adding more invents orderings the input never implied.

One practical tip

Two lines, before any code

Write the algorithm’s name, and what your heap tuple (or DSU / in-degree structure) actually holds — e.g. # Dijkstra; heap holds (total_time_so_far, node). Naming the algorithm and pinning down exactly what you’re minimising is what turns these from “hard” into “type the template.”
